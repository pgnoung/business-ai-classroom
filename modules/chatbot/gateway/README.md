# AI Gateway ของชุดผู้เรียน

Console → Gateway บน 127.0.0.1:8650 → OpenAI หรือ Anthropic (Claude)

ใช้เครื่องยนต์จาก source commit ที่ตรวจตรงกับ VPS ใช้งานจริงวันที่ 12 พ.ย. 2026 พร้อมปรับส่วนติดตั้งให้เป็นบัญชีของผู้เรียน
ตัวแปร HERMES_* เป็นชื่อเดิมของจุดเชื่อม AI; ระบบนี้ไม่ต้องติดตั้ง Hermes Agent

## เลือกและทดสอบ

1. `deploy` ลง `ai-admin.service` กับ `ai-admin-gateway.service` พร้อมกัน; ก่อนมีคีย์ Gateway แสดงว่ายังไม่พร้อม
2. ผู้เรียนรัน `secrets` ใน Terminal ของตัวเอง: OpenAI หลัก/สำรอง และ Claude หลัก/สำรอง (Claude เป็นตัวเลือก)
3. ใน Console เลือกโมเดลสำหรับ **ตอบแชต / ประเมินลูกค้า / ติดตาม** รายการเป็น catalog ของรุ่น ไม่รับรองว่าบัญชีมีสิทธิ์ทุกตัว
4. ตรวจสิทธิ์และราคาของบัญชี ณ วันติดตั้งก่อนใช้จริง; ข้อมูลราคาใน catalog เป็น snapshot
5. ตกลงค่าใช้จ่ายสำหรับข้อความสังเคราะห์หนึ่งครั้งต่อโมเดลที่เลือก รวม scorer fallback และ Claude fallback ถ้าอยู่ในรายการอนุญาต
6. รัน `bash ai-admin.sh model-test`; ผ่านเฉพาะเมื่อโมเดลที่ร้องขอตอบจริง การสลับไปตัวสำรองไม่นับว่าโมเดลต้นทางผ่าน
7. ทดลองคำถามธุรกิจและส่งต่อคนก่อน `golive on` ซึ่งต้องได้รับอนุญาตให้เปิด LINE ของร้านนั้น

`model-test` มีค่าใช้จ่ายตามผู้ให้บริการ; ไม่มีการเรียก AI เสียเงินอัตโนมัติตอนเริ่ม service
ใบยืนยัน setup อายุ 7 วัน ตรวจตรงกับโมเดลที่เลือกตอนเปิด LINE; เปลี่ยนคีย์ผ่าน secrets จะล้างใบเดิม
เปลี่ยนโมเดลหลังเปิด LINE แล้วต้องทดสอบใหม่ก่อนใช้งาน โมเดลใหม่ไม่ได้ถูกระงับอัตโนมัติด้วยใบยืนยันนี้
หน้า health แสดงความพร้อมแต่ละโมเดลหลังตอบสำเร็จ; ความพร้อมรวมอาจยังไม่ผ่านเมื่อยังไม่ได้ทดสอบครบ catalog
อย่าใช้ readiness รวมแทนหลักฐานทดสอบโมเดลที่ร้านเลือก

## การสลับเมื่อขัดข้อง

- OpenAI: เมื่อคีย์ถูกปฏิเสธด้วย 401/402/403/429 ลองคีย์สำรอง และรายงานหมายเลขช่องคีย์ที่ทำงาน
- Claude: รองรับสองคีย์; ถ้าเรียกไม่ได้ ให้ลอง OpenAI `gpt-6.1-sol` เฉพาะเมื่ออยู่ใน allowlist และมีคีย์ OpenAI
- เลือก Claude โดยยังไม่มีคีย์ Claude → ปฏิเสธคำขอ ไม่แอบใช้ OpenAI แทน
- ระบบไม่เลือกโมเดลตามราคาหรือเปลี่ยนผู้ให้บริการแบบไร้ขอบเขต; การเลือกโมเดลและ fallback ต้องตกลงก่อนใช้
- Whisper `whisper-1` รับข้อความเสียงผ่านเส้นทาง Gateway ที่จำกัดชนิดคำขอ/ขนาด ไม่ให้ Console อ่านคีย์ผู้ให้บริการ

## การเก็บคีย์และอัปเกรด

`/etc/ai-admin/gateway.env` อ่านได้เฉพาะ root และบัญชีบริการ Gateway; Console ได้เพียง local token
Gateway รับเฉพาะ loopback ไม่เปิด 8650 ออกอินเทอร์เน็ต ไม่มีการเก็บ mirror สำเนาคำถาม/คำตอบ
ข้อมูลแชตที่ Console ต้องเก็บยังอยู่ในฐานข้อมูลร้านตามปกติ และคำขอ AI ถูกส่งไปผู้ให้บริการที่เลือก

`update` หรือ `deploy` อัปเกรดทั้งคู่ เก็บคีย์/แบรนด์/ฐานข้อมูลเดิม และย้ายคีย์เดิมจาก direct API มายัง Gateway
หากเจอ endpoint ที่ปรับเอง ตัวติดตั้งจะหยุดเพื่อให้ตรวจการย้าย; ไม่เขียนทับโดยเดา
rollback รองรับคู่ release ที่มี Gateway เท่านั้น; รุ่นก่อนมี Gateway ต้องกู้ค่า config และ backup ที่ตรงรุ่นด้วยตนเอง
แพ็กนี้ยังไม่ได้พิสูจน์ fresh VPS, reboot หรือ disaster recovery บนบัญชีผู้เรียนจริง
