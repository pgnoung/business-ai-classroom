# รับข้อมูลร้านจากแชท → โฟลเดอร์ `business/`

ผู้ใช้จะส่งมาแบบไหนก็ได้: พิมพ์ยาว ๆ, วางเมนู, รูปเมนู/ป้ายราคา, รูปสินค้า, PDF แคตตาล็อก, ไฟล์ Excel/CSV, ลิงก์เว็บ/เพจร้าน,
ข้อความที่เคยตอบลูกค้า งานของคุณคือแปลงทั้งหมดเป็นไฟล์ตามแบบด้านล่าง **โดยไม่แต่งเพิ่ม** แล้วให้ผู้ใช้ยืนยัน

เริ่มครั้งแรก: คัดลอก `business-example/` เป็น `business/` แล้วลบเนื้อหาตัวอย่าง (ร้านกาแฟมะลิ) ทิ้งให้หมด — อย่าปล่อยข้อมูลตัวอย่างค้างไว้

## ไฟล์และช่อง

### `business.json` — ตัวตนร้านและกติกา
| ช่อง | ใส่อะไร | ถ้าไม่รู้ |
| --- | --- | --- |
| `businessId` | ชื่ออังกฤษสั้น a-z 0-9 - เช่น `cafe-mali` (ตั้งให้เองจากชื่อร้าน) | ตั้งให้ |
| `businessName` | ชื่อร้านตามที่ลูกค้าเห็น | **ถาม** |
| `agentName` | ชื่อ AI แอดมิน เช่น "น้องมะลิ" | เสนอ 3 ชื่อให้เลือก |
| `ownerName` | AI จะเรียกเจ้าของ/ทีมว่าอะไร เช่น "พี่เจ้าของร้าน", "ทีมงาน" | ใช้ "ทีมงาน" |
| `agentGender` | `female` (ค่ะ/คะ — แนะนำ) · `male` · `neutral` — ตอนนี้ข้อความสำเร็จรูปของระบบ (เช่น ตอนระบบขัดข้อง) ลงท้าย ค่ะ เสมอ | ใช้ `female` |
| `businessType`, `about` | ขายอะไร ให้ใคร จุดเด่นจริงที่ผู้ใช้บอก | เว้นว่าง |
| `tone` | น้ำเสียง เช่น "เป็นกันเอง ตอบสั้น" | "สุภาพ เป็นกันเอง ตอบสั้น" |
| `contact` | `phone`, `lineId`, `hours`, `address`, `website` | เว้นว่าง |
| `payment` | `methods` (รายการ), `notes` | **ถาม** — ห้ามใส่เลขบัญชีให้ AI ส่งเอง แนะนำให้ทีมส่งหลังยืนยันออเดอร์ |
| `shipping` | `areas`, `fee`, `days` | ถาม ถ้าเป็นร้านที่ส่งของ |
| `policies` | `returns`, `warranty`, `other` | เว้นว่าง |
| `handoffRules` | เมื่อไรต้องส่งให้คน (รายการ) | ใส่ค่าเริ่มต้น: ร้องเรียน, ส่งสลิป, สั่งจำนวนมาก/งานพิเศษ, คำถามที่ไม่มีข้อมูล |
| `forbidden` | สิ่งที่ AI ห้ามทำ (รายการ) | ใส่ค่าเริ่มต้น: ห้ามให้ส่วนลดเอง, ห้ามสัญญาสิ่งที่ไม่มีในข้อมูล |

### `products.json` — สินค้า/บริการ (รายการ)
`{"id","name","price","unit","category","description","aliases","image","active"}`
- `id` a-z 0-9 - ไม่ซ้ำ และ**ห้ามเปลี่ยนภายหลัง** (ใช้จับคู่ตอนนำเข้าซ้ำ) เช่น `latte-hot`
- `price` ตัวเลขล้วน (บาท) — ราคามีหลายขนาด = แยกเป็นหลายรายการ (`latte-hot-16oz`, `latte-hot-22oz`)
  ราคาไม่ตายตัว/ต้องประเมิน = `null` (AI จะไม่บอกราคาและส่งให้ทีม)
- `aliases` คำที่ลูกค้ามักเรียก รวมสะกดผิด/อังกฤษ
- `image` path ใน `business/images/` (**jpg หรือ png** ≤ 5 MB — LINE ส่ง webp ไม่ได้) — ตั้งชื่อไฟล์ตาม id
- ของที่เลิกขาย: `"active": false` (อย่าลบรายการ เพื่อให้นำเข้าซ้ำแล้วปิดได้ถูก)

### `faq.json` — คำถามที่พบบ่อย `[{"question","answer"}]`
ใช้คำตอบตามที่ผู้ใช้เขียน (เกลาให้อ่านง่ายได้ แต่ห้ามเปลี่ยนความหมาย/ตัวเลข)

### `knowledge/*.md` — ความรู้อื่น
หนึ่งไฟล์ = หนึ่งเรื่อง บรรทัดแรก `# หัวข้อ` เช่น โปรโมชัน, วิธีใช้สินค้า, ขั้นตอนสั่งทำ, ข้อมูลไซซ์

## วิธีแปลงจากของที่ผู้ใช้ส่ง

- **รูปเมนู/ป้ายราคา/PDF**: อ่านทุกบรรทัดแล้วถอดเป็นตาราง ระบุบรรทัดที่อ่านไม่ชัดด้วย ❓ ให้ผู้ใช้ยืนยัน
- **รูปสินค้า**: คัดลอกไปที่ `business/images/<id>.<นามสกุลเดิม>` ถ้าเดาไม่ได้ว่าเป็นสินค้าไหน ให้ถาม · ไฟล์ HEIC/webp แปลงเป็น jpg ก่อน (macOS: `sips -s format jpeg in.heic --out out.jpg` · หรือให้ผู้ใช้ส่งเป็น jpg)
- **Excel/CSV**: อ่านคอลัมน์ ชื่อ/ราคา/รายละเอียด ตรงตามไฟล์
- **ลิงก์เว็บ/เพจ**: อ่านได้เฉพาะหน้าที่เปิดสาธารณะ ใช้เป็นแหล่งข้อมูลแล้วยืนยันกับผู้ใช้ — ข้อมูลบนเว็บอาจเก่า
- **แชทเก่ากับลูกค้า**: ใช้เป็นแนวคำตอบ FAQ และน้ำเสียง แต่**ห้ามคัดลอกชื่อ/เบอร์/ที่อยู่ลูกค้า**ลงไฟล์ใด ๆ
- ข้อมูลขัดกัน (ราคาสองที่ไม่เท่ากัน) → ถาม อย่าเลือกเอง

## ก่อนนำเข้า: ให้ผู้ใช้ยืนยัน

แสดงสรุปแบบนี้ แล้วรอคำว่า "ยืนยัน" (หรือแก้ตามที่บอก):

```
ร้าน: ร้านกาแฟมะลิ · AI ชื่อ น้องมะลิ (ค่ะ) · เรียกเจ้าของว่า พี่เจ้าของร้าน
สินค้า 4 รายการ:
| # | สินค้า | ราคา | รูป |
| 1 | ลาเต้ร้อน | 65 บาท/แก้ว | ✅ |
| 4 | เค้กสั่งทำ | ทีมประเมิน | — |
FAQ 3 ข้อ · ความรู้เพิ่ม 1 เรื่อง (โปรโมชันเดือนนี้)
จ่ายเงิน: โอน/พร้อมเพย์ (ทีมส่งเลขบัญชีเอง) · ส่ง: ในเมือง ≤10 กม. เริ่ม 30 บาท
ส่งให้คนเมื่อ: ร้องเรียน, ส่งสลิป, สั่งเกิน 20 แก้ว, ไม่มีข้อมูล
ยังขาด: (ถ้ามี)
```

จากนั้น `ai-admin import` (แผน) → ถ้าตัวตรวจบนเซิร์ฟเวอร์แจ้งปัญหา ให้แก้แล้วรันใหม่ → `ai-admin import --apply`
→ `ai-admin chat --new "<คำถามเกี่ยวกับสินค้าที่เพิ่งใส่>"` ยืนยันว่า AI ใช้ข้อมูลใหม่แล้ว

## นำเข้าซ้ำ

ทำซ้ำได้เสมอ: รายการที่มี `id` เดิมถูกอัปเดต · `active:false` ถูกปิด · ของที่สร้างในหน้า console เองไม่ถูกแตะ
(แนะนำให้ผู้ใช้แก้สินค้าผ่าน `business/` ทางเดียว เพื่อไม่ให้ข้อมูลสองที่ไม่ตรงกัน)
